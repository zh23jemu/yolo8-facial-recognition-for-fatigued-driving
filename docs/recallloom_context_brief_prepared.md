<!-- section: mission -->
# 项目使命

- 维护一个围绕疲劳驾驶面部识别的毕业设计项目，覆盖算法训练、推理演示、论文撰写和用户交付四条主线。
- 以 YOLOv8n 为基线，在闭眼、睁眼、打哈欠三类疲劳相关面部特征检测任务上完成可复现的模型改进、实验分析和桌面端演示。

<!-- section: audience_stakeholders -->
# 受众与相关方

- 直接使用者包括项目作者、导师、毕业答辩评审以及接收交付包的最终用户。
- 协作关注点分为两类：一类是论文与实验材料完整性，另一类是程序在用户电脑上的可运行性与交付稳定性。

<!-- section: current_phase -->
# 当前阶段

- 项目已完成主要代码、训练权重、论文结构重组和用户交付包打包。
- 当前处于交付与兼容性收尾阶段，重点是解决客户电脑上的运行问题，并持续沉淀项目连续性记录。

<!-- section: scope -->
# 范围

- 项目范围包括：YOLOv8n 基线模型、CBAM 改进模型、疲劳状态规则判断、PyQt5 桌面演示程序、训练脚本、论文正文与用户打包材料。
- 当前不把真实车载部署、跨平台安装器、长期在线监控服务纳入必做范围。

<!-- section: source_of_truth -->
# 事实来源

- 代码与配置以 `src/`、`configs/`、`scripts/`、`weights/` 为准。
- 论文与项目说明以 `docs/thesis_draft.md`、`docs/thesis_draft.docx`、`README.md`、`docs/user_package_readme.md` 为准。
- 交付物以项目根目录生成的压缩包和其中的 `README.md` 为准。

<!-- section: core_workflow -->
# 核心工作流

- 修改代码前先读取目标文件与现状，再做最小必要修改。
- 文档改动优先维护 Markdown 源稿，再重新生成 DOCX 并做渲染校验。
- 用户交付优先整理“程序 + 模型 + 说明”，需要时再附带 `data.zip` 数据集。
- 桌面程序兼容性问题优先通过入口初始化、相对路径与依赖稳定性解决，而不是只依赖本机环境偶然可用。

<!-- section: boundaries -->
# 边界与约束

- 所有对外说明默认使用简体中文。
- Python 运行优先使用项目本地 `.venv`。
- 不使用破坏性文件删除命令；交付包应尽量只包含用户需要的内容。
- 对于 `RecallLoom` 侧边文件，后续写入应优先使用其脚本接口而不是手工改动状态文件。
